# add-guided-notes-import 驗證紀錄

## 1. 驗證環境

- 作業系統：Windows 11
- Node.js：v24.22.0
- 啟動方式：`node server/index.js`（`PORT=3456`，`NODE_ENV` 未設定，即 production 行為）
- 瀏覽器：Claude Code 桌面版內建瀏覽器（Chromium）

## 2. 自動測試

| 指令 | 結果 |
| --- | --- |
| `npm test` | 65 項全數通過（既有 25 項、解析模組 19 項、匯入 API 12 項、教師頁邏輯 9 項） |
| `npm run check:capacity` | 100 條 SSE 連線、50 題，最大延遲 16 ms，全數在 2 秒內收到 |

解析模組對 `fixtures/guided-notes/` 的 5 份有效學習單，工作表、表頭列、題號、空格數、前綴與作答區位置皆與 `expected.json` 一致；3 份無效學習單分別得到 `IMPORT_NO_HEADER`、`IMPORT_DUPLICATE_NUMBER`、`IMPORT_NO_QUESTIONS`。

## 4. 教師頁瀏覽器驗證（tasks 4.3）

檔案選擇以腳本把測試學習單放入檔案欄位（內建瀏覽器無法操作系統的選檔對話框），其餘為實際點擊按鈕。

| 步驟 | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 1 | localhost 讀取 `02-official-group.xlsx` 後按取消 | 摘要收起，題數維持原值 | 通過 |
| 2 | 再讀取並確認 | 顯示 4 題、6 個空格，`questionCount` 為 4，檔案欄位清空 | 通過 |
| 3 | 摘要內容 | 第 1、2 題為題組並顯示「（1）（2）」，提示「確認後會取代目前的題目」 | 通過 |
| 4 | 讀取 `90-invalid-no-header.xlsx`、非 xlsx 文字檔、非 Google 連結 | 各自顯示對應錯誤，題數不變 | 通過 |
| 5 | 以 `http://127.0.0.1:3456/teacher/` 開啟 | 匯入操作可用，顯示目前匯入狀態 | 通過 |
| 6 | 以 `http://<區網IP>:3456/teacher/` 開啟 | 顯示警告、匯入操作停用 | 通過 |
| 7 | 開始搶答後重新整理教師頁 | 匯入停用並顯示「只能在準備中匯入」 | 通過 |
| 8 | 以 localhost、127.0.0.1、區網 IP 三個來源的學生頁進場 | 三位學生分別進入第 1、2、1 組，不受匯入影響 | 通過 |

## 6. 驗證中發現並修正的問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| 讀取合併範圍內非左上角的格子時程式出錯 | `exceljs` 的 `cell.text` 對合併範圍的從屬格會讀到空值 | 一律回到合併範圍左上格取值，並自行轉換文字 |
| 以區網 IP 開啟教師頁時顯示「尚未匯入學習單」 | 區網來源無法查詢匯入狀態，畫面誤用了「沒有匯入」的文字 | 改為提示「請以 localhost 開啟本頁才能查看匯入狀態」 |

## 7. 其他觀察

- 學生頁剛載入、尚未收到第一個 SSE 事件時會短暫顯示「重新連線中…」，最多 15 秒後收到心跳即消失。此行為屬於 `groups-and-entry`，與本 change 無關，需轉告學生端成員。
- `npm audit` 回報 `exceljs` 依賴的 `uuid` 有中度風險，`exceljs` 只使用 v4，不受影響，見 design.md。

## 8. 已知限制

server 重啟後匯入結果與其他記憶體狀態一樣清空，需要重新匯入。
