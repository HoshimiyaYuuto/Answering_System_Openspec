# add-guided-notes-import 驗證紀錄

## 1. 驗證環境

- 作業系統：Windows 11
- Node.js：v24.22.0
- 啟動方式：`node server/index.js`（`PORT=3456`，`NODE_ENV` 未設定，即 production 行為）
- 瀏覽器：Claude Code 桌面版內建瀏覽器（Chromium）

## 5. 人工驗證（tasks 5.2）

2026-11-18，教師端成員在本機 Chrome 開啟 `http://localhost:3000/teacher/` 操作（`npm start`，`NODE_ENV` 未設定）。

### 5.1 Google 試算表連結

| 步驟 | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 1 | 貼上助教提供的官方題組範本連結，按「讀取連結」 | 來源「軟工期末專案_題組_範例.xlsx」，4 題、6 個空格，第 1、2 題為題組並顯示「（1）（2）」，第 3、4 題為單題 | 通過 |
| 2 | 按「確認匯入」 | 顯示已匯入 4 題、6 個空格 | 通過 |
| 3 | 把官方範本「建立副本」到自己的雲端硬碟，一般存取權設為「知道連結的任何人」（檢視者），以副本連結讀取 | 摘要與步驟 1 相同；按取消後題目不變 | 通過 |
| 4 | 把副本的一般存取權改回「限制」，以同一連結再讀取 | 顯示「無法下載這份試算表。請確認已設為『知道連結者可檢視』，或改用上傳 xlsx。」，仍為 4 題 | 通過 |

另以 server 端直接下載兩份官方範本連結比對：單題範本 6 題、6 格；題組範本 4 題、6 格，題組答案寫入位置為 H5/H6、H8/H9，與 `fixtures/guided-notes/` 的 01、02 解析結果相同。

## 6. 驗證中發現並修正的問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| 讀取合併範圍內非左上角的格子時程式出錯 | `exceljs` 的 `cell.text` 對合併範圍的從屬格會讀到空值 | 一律回到合併範圍左上格取值，並自行轉換文字 |
| 以區網 IP 開啟教師頁時顯示「尚未匯入學習單」 | 區網來源無法查詢匯入狀態，畫面誤用了「沒有匯入」的文字 | 改為提示「請以 localhost 開啟本頁才能查看匯入狀態」 |

## 7. 其他觀察

- 學生頁剛載入、尚未收到第一個 SSE 事件時會短暫顯示「重新連線中…」，最多 15 秒後收到心跳即消失。此行為屬於 `groups-and-entry`，與本 change 無關，需轉告學生端成員。
- `npm audit` 回報 `exceljs` 依賴的 `uuid` 有中度風險，`exceljs` 只使用 v4，不受影響，見 design.md。

## 8. 已知限制

server 重啟後匯入結果與其他記憶體狀態一樣清空，需要重新匯入。
