# add-teacher-console 驗證紀錄

## 1. 驗證環境

- 作業系統：Windows 11
- Node.js：v24.22.0
- 啟動方式：`node server/index.js`，專案根目錄的 `.env` 設定 `PORT=3000`、`TEACHER_PASSWORD`（本機測試用密碼，不提交），`NODE_ENV` 未設定（production 行為）
- 瀏覽器：Claude Code 桌面版內建瀏覽器（Chromium），同時開啟四個分頁：
  - 教師 A：`http://localhost:3000/teacher/`
  - 教師 B：`http://192.168.101.118:3000/teacher/`（本機 Wi-Fi 區網位址）
  - 學生 1：`http://127.0.0.1:3000/student/`
  - 學生 2：`http://192.168.101.118:3000/student/`
- 日期：2026-11-21

| 步驟 | 操作 | 預期 | 結果 |

## 5. 人工驗證（tasks 4.2）

### 5.1 完整流程

第 4 節步驟 2～8 即為「登入 → 設定組別 → 匯入 → 開始 → 結束」的完整流程：老師分別以 localhost（教師 A）與區網位址（教師 B）登入操作，兩位學生分別來自 127.0.0.1 與區網位址。

### 5.2 嘗試次數限制

| 步驟 | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 1 | 教師 A（localhost）連續輸入 10 次錯誤密碼 | 每次顯示密碼錯誤 | 通過 |
| 2 | 第 11 次輸入正確密碼（08:35:37 UTC） | 顯示「嘗試次數過多，請稍後再試。」，仍在登入畫面 | 通過 |
| 3 | 限制期間教師 B（區網位址）以正確密碼登入 | 登入成功，不受教師 A 的限制影響 | 通過 |
| 4 | 第一次錯誤超過 60 秒後（08:36:55 UTC），教師 A 以正確密碼登入 | 登入成功 | 通過 |

## 6. 驗證中發現並修正的問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| server 重新啟動後，停在「已結束」的控制台不會回到登入畫面 | 已結束時除了登出以外的按鈕都停用，老師沒有操作可以觸發 `401`；SSE 自動重連後頁面也沒有重新讀取狀態 | SSE 連上或重新連上時重新讀取活動摘要與匯入狀態，登入失效時由 `401` 帶回登入畫面（契約已規定重連後以 `GET /api/session` 取得快照） |
| 驗證時第一次啟動的 server 不是新程式 | 11/18 啟動的舊 `node server/index.js` 仍占用 3000 埠，停止 `npm start` 時只結束了外層程序 | 結束舊程序後重新啟動；驗證環境問題，與程式無關 |

## 7. 其他觀察

- 第 4 節步驟 8：第一個分頁確認結束後，SSE 在第二個分頁按下確認前就送達，第二個分頁的確認列自動收起並顯示已結束，因此實際操作沒有走到「server 回 `409`、畫面視為成功」的路徑。該路徑由 `console-logic.test.js` 的「ending twice shows 已結束 without an error」與 server 對重複結束回 `409 INVALID_PHASE_TRANSITION` 的測試涵蓋。
- 本機有 VMware 等虛擬網卡，區網位址需選 Wi-Fi 網卡的位址（本次為 `192.168.101.118`）。
