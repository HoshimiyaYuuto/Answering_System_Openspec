# add-groups-and-student-entry 驗證紀錄

## 1. 驗證環境

- 作業系統：Windows
- Shell：PowerShell
- 啟動方式：`npm start`
- `NODE_ENV`：空（production 行為）
- 自動測試：使用者在本機執行 `npm test`，全部通過。
- Codex 沙盒：因 `spawn EPERM` 無法執行測試。

## 2. 多學生模擬方法

同一瀏覽器、同一來源（網址）的所有視窗與分頁共用同一份 `localStorage`，因此視為同一個學生。使用不同來源模擬不同學生：

- `http://localhost:3000/student/`
- `http://127.0.0.1:3000/student/`
- `http://<區網IP>:3000/student/`
- Edge InPrivate 視窗：模擬搶答中首次進場的新學生。

## 3. 整合驗收結果

| 項目 | 操作 | 預期 | 結果 |
| --- | --- | --- | --- |
| 多學生選組 | 教師頁產生 5 組；兩個學生選不同組，第三個學生選同組 | 三個學生依選擇進場，同組允許多人使用 | 通過 |
| 重新整理恢復 | 進場後重新整理學生頁 | 恢復原組別與目前階段 | 通過 |
| 準備中換組 | 準備中在學生頁更換組別 | 換組成功 | 通過 |
| 移除組別 | 教師移除一組後，該組學生重新整理 | 回到選組畫面並顯示「組別已被老師移除」，`studentId` 保留；其他學生不受影響 | 通過 |
| 開始搶答 | 教師開始活動 | 已進場學生兩秒內顯示搶答中，且沒有換組按鈕與題目 | 通過 |
| 搶答中首次進場 | 搶答中以全新視窗首次選組 | 進場成功，不顯示失效訊息 | 通過 |
| 搶答中換組 | 搶答中嘗試更換組別 | server 回 `409 GROUP_CHANGE_NOT_ALLOWED` | 通過 |
| 結束活動 | 教師結束活動 | 學生畫面顯示已結束 | 通過 |
| 斷線與重啟 | 斷線超過 40 秒，再重新啟動 server | 顯示「重新連線中」；重啟後自動回到選組畫面、顯示「進場狀態已失效」說明，組別清單為最新 | 通過 |
| 教師端 loopback 限制 | 以區網 IP 開啟教師頁並嘗試設定 | 頁面顯示警告並停用操作，API 回 `403 LOOPBACK_ONLY` | 通過 |
| 學生端區網存取 | 以區網 IP 開啟學生頁（`window.isSecureContext` 為 false）並選組 | 選組成功 | 通過 |

## 4. 未驗證項目

真實手機未驗證（環境限制：有線網路、無分享器）；以電腦瀏覽器透過區網 IP 開啟作等效驗證。

## 5. 驗證中發現並修正的問題

| 問題 | 原因 | 修正 |
| --- | --- | --- |
| 等待畫面的階段說明出現兩行 | 固定文字與動態文字同時存在 | 只保留一個由程式更新的元素 |
| 重啟 server 後各視窗顯示的組別清單不一致 | 選組畫面沿用舊清單 | 每次顯示選組畫面都重新讀取 |
| 組別清單重複出現 | 重新整理時以附加方式繪製，且多個請求回應互相覆蓋 | 取代內容並丟棄過期回應 |
| 全新使用者誤報「進場狀態已失效」 | 選組前就產生並保存 `studentId` | 只有 `PUT` 成功後才保存 |
| `group_removed` 與 `entry_reset` 顯示同一句 | 兩種原因共用說明文字 | 改為各自顯示不同說明 |
| 自動測試偽造標頭案例沒有真的模擬非 loopback | 測試請求原本連到 `127.0.0.1` | 改為連到區網位址 |

## 6. 已知限制

伺服器重啟後記憶體狀態清空；本 change 明確不做持久化。
