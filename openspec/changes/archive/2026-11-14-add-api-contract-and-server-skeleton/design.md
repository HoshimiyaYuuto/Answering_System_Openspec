# Design

## Context

目前 repository 只有 OpenSpec 與前端目錄，尚無 server、API 契約或執行相依。專案要求本機運作、同網段可連線、輕量實作，並以 server 作為階段唯一權威。學生進場與作答、教師登入與管理、倒數等由後續 change 擴充。

## Goals / Non-Goals

**Goals:**
- 固定第一階段 API 路徑、JSON envelope、錯誤 code 與階段語意。
- 建立可啟動、可供同網段存取的 server，並用可替換的推送介面廣播階段。
- 讓未知路徑和未預期錯誤也符合 JSON 契約。

**Non-Goals:**
- 本 change 不實作學生進場、組別管理、作答排序、教師登入、題目匯入匯出、倒數或結果。
- 不提供重啟後持久化；初始狀態存在記憶體。
- 不實作 D19 活動重設；後續 change 須以 MODIFIED 調整階段「僅能前進」要求並新增獨立重設操作。
- 不在正式流程提供假資料或階段切換介面；開發種子與切換指令僅能在開發環境啟用。

## Decisions

- **Node.js + Express，提供 REST API。** 選擇 Explore 建議的輕量組合，降低前後端整合成本；替代方案是原生 HTTP server，雖少一項相依，但路由與錯誤處理需自行搭建。
- **使用 SSE 傳送階段事件。** 階段更新是 server 至 client 的單向訊息，SSE 比 WebSocket 簡單；契約將傳輸與事件欄位寫清楚，以便日後替換。建立連線時另以摘要 API 取得當前快照。
- **將 API 契約維護在 `docs/api-contract.md`。** 先記錄摘要查詢、階段控制、事件、錯誤 envelope 與狀態碼；具體端點需與此契約一致。
- **階段由 server 記憶體狀態機管理。** 只允許準備中→搶答中→已結束；控制操作由 server 驗證轉移。階段控制端點預設只接受 loopback 請求。後續教師端 change 以環境變數密碼驗證取代 loopback 限制，再允許教師端操作。
- **摘要與 SSE 事件附 server 時間，串流定期心跳。** 時間戳由 server 產生；心跳不改變活動狀態。client 斷線重連後以摘要快照校正狀態。
- **開發種子與控制命令隔離。** 僅在明確的 development 環境載入固定假題目與組別資料，並提供切換階段的開發測試指令；production 啟動不得載入種子，亦不得註冊測試控制路由。以啟動環境與路由檢查驗證隔離。
- **綁定可設定的主機介面以供區網讀取。** 密碼與金鑰從環境變數載入；版本庫只提供不含真值的 `.env.example`，並忽略實際 `.env`。階段控制仍限 loopback，直到教師端驗證完成。
- **以可重現負載驗證 SSE 容量。** 建立 100 個 SSE client 並使用至少 50 題資料，記錄階段變化發出至最後一個 client 收到的延遲；目標為兩秒內全數收到。
- **loopback 判斷方式。** 以連線實際來源位址判斷，不信任 `X-Forwarded-For` 等轉發標頭，並接受 `127.0.0.1`、`::1`、`::ffff:127.0.0.1`。教師端須以 `localhost` 開啟（用區網 IP 開啟會被拒絕），此要求寫入契約與後續 README。
- **環境預設為 production。** 環境變數未設定時一律視為 production，不載入種子資料，也不註冊測試控制路由。
- **心跳間隔為 15 秒。** 契約記載此數值，作為心跳驗證標準。

## Risks / Trade-offs

- SSE 在代理或瀏覽器休眠情境可能中斷 → 事件串流中斷後由 client 重連，並重新讀取摘要快照。
- 記憶體狀態在重啟後消失 → 此為本 change 明確限制，持久化另列後續工作。
- 尚未納入教師登入 → 階段控制在此版只供本機開發整合，部署前須由教師端 change 加上環境變數密碼驗證。
- 開發控制路由若誤進正式環境可能改變活動 → 路由註冊同時檢查 development 環境，並以 production 驗證確認不存在。

## Migration Plan

新增文件與 server 骨架，不需搬移既有資料。回退時移除此 change 新增的 server 與契約文件即可；不涉及資料庫遷移。

開發驗證可用專案提供的 seed 與階段切換命令；命令只在 development 環境有效，不作為正式操作流程。
